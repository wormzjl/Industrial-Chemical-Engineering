# compound-import

Purpose: copy the ChemSep v8.3 pure-component data and the PR interaction files out of the local DWSIM install, and turn a selection of compounds into IChemE material records (`components`, `properties` with the `freezing` sub-record, a PR78 pair library, liquid volume reference points), with a cross-check against the batch data document and a regression check against the bundled light ends.

Batch: [2026-11-04-refinery-compounds](../../documentation/2026-11-04-refinery-compounds/README.md), plan package W5 (PACKAGE_REWORK_PLAN.md sections 3.5 to 3.7, decisions D3, D6, Q4).

Status: In progress since 2026-11-04. Index: [../INDEX.md](../INDEX.md).

The DWSIM files are data: the scripts parse them as text and run nothing from them. ChemSep is Copyright Harry Kooijman and Ross Taylor, Artistic License 2.0; every record the import writes credits its ChemSep record.

## How to run

From the repository root (Node 22; Windows PowerShell 5.1 for the extract):

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/compound-import/Extract-DwsimData.ps1 -OutDir tmp/dwsim-data
node tools/compound-import/import.mjs tmp/dwsim-data tools/compound-import/selection-tier1.json tmp/compound-import/tier1
node tools/compound-import/import.mjs tmp/dwsim-data tools/compound-import/selection-regression.json tmp/compound-import/regression
node tools/compound-import/regression.mjs tmp/dwsim-data tools/compound-import/selection-regression.json tmp/compound-import/regression src/main/resources/data/icheme/materials
node tools/compound-import/import.mjs tmp/dwsim-data tools/compound-import/selection-freezing-existing.json tmp/compound-import/existing-freezing --materials src/main/resources/data/icheme/materials
node tools/compound-import/import.mjs tmp/dwsim-data tools/compound-import/selection-thermochemistry-existing.json tmp/o9-combustion/s2-import --materials src/main/resources/data/icheme/materials
node tools/compound-import/insert-subrecord.mjs thermochemistry tmp/o9-combustion/s2-import/thermochemistry src/main/resources/data/icheme/materials [--replace]
node tools/compound-import/insert-subrecord.mjs flammability tmp/o9-combustion/s2-import/flammability src/main/resources/data/icheme/materials [--replace]
```

Group tables, group counts and Henry constants (batch 2026-11-11-aqueous-solvents, W2a; `tmp/dwsim-groups` is an extract with the group tables and `chemsep1.xml` only, which is enough for these):

```
node tools/compound-import/groups.mjs tmp/dwsim-groups src/main/resources/data/icheme/materials/group_interactions/modified_unifac_dortmund.json
node tools/compound-import/import.mjs tmp/dwsim-groups tools/compound-import/selection-aqueous-existing.json tmp/w2-check/aqueous-import --materials src/main/resources/data/icheme/materials
node tools/compound-import/insert-subrecord.mjs group_counts tmp/w2-check/aqueous-import/group_counts src/main/resources/data/icheme/materials [--replace]
node tools/compound-import/insert-subrecord.mjs henry_in_water tmp/w2-check/aqueous-import/henry_in_water src/main/resources/data/icheme/materials [--replace]
node tools/aqueous-solvents/dortmund-values.mjs tmp/dwsim-groups
```

Authored group counts and the pilot overlay (same batch, W2b):

```
node tools/compound-import/import.mjs tmp/dwsim-groups tools/compound-import/selection-aqueous-authored.json tmp/w2-check/authored-import --materials src/main/resources/data/icheme/materials

```

Water as a compound of the cubic in main data (same batch, W3b step 2):

```
node tools/compound-import/import.mjs tmp/dwsim-groups tools/compound-import/selection-aqueous-main.json tmp/w3b-engine-kernel/main-import --materials src/main/resources/data/icheme/materials
```

The pilot import's `components/ethanol.json` and `properties/pilot_ethanol.json` are copied into the test overlay `src/test/resources/materials/pilot-aqueous/`, never into main data. Its `properties/pilot_water.json` is no longer copied: since W3b step 2 the main import's `properties/cubic_water.json` (same values, `icheme:cubic_water`) is copied into main data, and the pilot reads it.

`import.mjs` options: `--data <md>` (the cross-check document; default the batch's REFINERY_COMPOUNDS_DATA.md), `--materials <dir>` (bundled records, for the crude-fraction molar masses and the crystal anchors).

Parser check (plain `javac`, no Gradle; reads `src/`, writes only `tmp/`): compile `parse-check/ParseCheck.java` with `-sourcepath src/main/java` and the Gson 2.10.1, EJML 0.44.0 and JetBrains annotations jars from the Gradle cache, then `java ParseCheck src/main/resources tmp/compound-import/tier1`. It parses the bundled resources plus the import output through `MaterialCatalog.parse`, builds a package (the network package extended by the imported compounds, `crude_pr78` with the imported pair library after `tjl20`), checks every written pair resolves to its value, and builds `HydrocarbonModel`, which requires a PR78 liquid root at every volume anchor.

## Conversions

- Ideal-gas Cp (eq. 16, 100 or 107; J/kmol/K to J/mol/K): unweighted least squares, `shifted_polynomial_5`, on every 25 K multiple of the fit range. The bundled light ends sampled 300, 325, ..., 900 K (`include_low_end: false` reproduces their coefficients to 1e-11). Tier 1 fits from max(ChemSep Cp data start, triple point) to 900 K, with the low end as the first point; that range is also the record's `fluid_domain` temperature range. Below it the network holds Cp with a notice: a data-range end, never a validity floor.
- Viscosity (eq. 101 liquid, eq. 102 vapour), at 100 kPa as the bundled tables: a log table by recursive bisection, an interval kept when log interpolation is within 0.05 % at its quarter and mid points (at most 2^8 intervals). This reproduces the 12 bundled DWSIM-sampled light-end tables node for node. Liquid: bundled form 0.5..0.95 Tc; Tier 1 max(data start, triple point)..0.95 Tc, and past the equation's data end ln(mu) linear in 1/T at its slope there (Andrade), marked estimated. Vapour: the fluid-domain start (or data start) to 900 K (or data end); the parser continues it past the ends.
- Standard liquid density: eq. 105 at 288.7056 K and 101325 Pa, as the bundled light ends (reproduced to 5e-13). A compound with Tc below 288.7 K takes its saturated liquid at Tr = 0.7 instead, with that temperature and pressure (nitrogen's precedent: its own liquid point).
- Liquid volume reference points: the saturated liquid at Tr = 0.7, molar volume from eq. 105 and pressure from eq. 101, for every imported compound; no compound takes a hypothetical 60 F liquid. `report.json` gives the PR78 liquid root and the shift at each point.
- `freezing`: ChemSep melting point, triple point temperature and pressure, heat of fusion at the melting point, its own revision. CO2 takes the `crystal_carbon_dioxide_i` anchor (`from_crystal`, on a `freezing_only` entry or, since O11, on an imported compound); water has none (its water model holds 273.16 K and its ice); crude fractions take the Riazi and Al-Sahhaf 1995 n-paraffin bound, estimated (Q4). The revision names the source: the selection's `freezing_revision` for ChemSep, `estimate_freezing_revision` for the crude-fraction estimate and `crystal_freezing_revision` for a crystal anchor (each defaults to `freezing_revision`).
- `thermochemistry` and `flammability` (O9 form S2, owner decision E23): ChemSep's ideal-gas heat of formation at 298.15 K (`HeatOfFormation`, J/kmol to J/mol) and the element formula (C, H, N, O, S), which must give ChemSep's molar mass within 0.02 g/mol; O2 and N2 are 0 by definition (`reference_element`, checked against ChemSep). Heats of combustion are left to Hess. Limits from the selection (NIOSH Pocket Guide or Bulletin 627 Table A-1), as volume fractions, in a separate sub-record; an entry without limits gets none. Each sub-record has its own revision; the record's revision does not move.
- `group_counts` (batch 2026-11-11-aqueous-solvents, plan M3), written for every imported compound and for `groups_only` entries: ChemSep's `ModifiedUnifac` element (Dortmund subgroup numbers) and its `GCmethod name="PPR78"` (E-PPR78 group numbers 1..40), each number named by the bundled `group_interactions` records (`modified_unifac_dortmund.json`, `eppr78_2022.json`; `--materials`, else this repository's), one entry per scheme with its own revision (`group_counts_revisions`, default `chemsep-8.3-modfac-r1` and `chemsep-8.3-ppr78-r1`). A scheme is refused for a compound, by name in the report, when ChemSep has no element for it, a number has no name (ethanol's and methanol's PPR78 group 41), or the two schemes count different aromatic, alkenic or ring carbons: neither invents a ring or a double bond, so the scheme that counts fewer has put such a carbon in a plain alkane group (ChemSep's PPR78 counts for cyclohexane, propylene, butene-1, isobutene and butadiene; its Dortmund counts for ethylene). Crude cuts get none. `groups.mjs` renames Dortmund subgroup 26 (`CHO`, the ether, a repeat of subgroup 20's name) to `CHO_ether` and 83 to `c-CH2O[1/2CH2]` (no space), and leaves out the `modfac_ip.txt` placeholder lines (all zero), the lines 14 43 and 2 56 (fields not readable by position) and the pairs of main group 49 (no subgroup in `modfac.txt`).
- `authored_counts` (W2b): an entry's own counts for a scheme, `{scheme: {revision, counts: {group name: n}}}`, written in place of ChemSep's (and of its refusal); each group name must exist in the scheme's table and each count be a positive integer. Ethylene's Dortmund count is CH2=CH 1, the nearest subgroup (Dortmund has no CH2=CH2); the E-PPR78 `CH2_alkenic` group is taken as the =CH2 and =CH- carbons.
- `homomorph` (W2b): `{component, revision}` on a compound entry, written into its properties record; the catalog requires a known component with a default dataset, not the compound itself. The derivation reads the homomorph's own E-PPR78 counts and critical constants.
- `no_pair_library` (W2b): the selection writes no pair library. `groups_only` entries may omit `cas` when they carry `authored_counts` for every scheme.
- `cubic_water` (W2b): a properties record for water as a cubic compound from the selection's Tc, Pc, acentric factor, Mathias-Copeman alpha, Tb, density and counts, with the ideal-gas Cp of the bundled water model's Shomate form refitted to `shifted_polynomial_5` (same 25 K grid). With `from_crystal` (W3b step 2) its freezing sub-record is the crystal's anchor, as for an imported compound.
- `henry_in_water` (same batch), for a compound entry with `henry_in_water: {coefficients}` and for `henry_only` entries: IAPWS G7-04 A, B, C with the selection's `henry_source` and `henry_revision`. The coefficients in `selection-aqueous-existing.json` are those of the guideline's Table 2 (checked 2026-11-11).
- `kij_pr.dat` N2-row erratum (decision E28, batch 2026-11-04-open-thermo-data), in `pairs.mjs`: after the diagonal the N2 row is shifted one cell to the left, and the N2 column copies two of the shifted cells. Evidence: the row's H2O cell holds -0.0193 while the H2O row's N2 cell is blank (-0.0193 is DECHEMA's N2/CO2, p310); its CO2 cell holds 0.1652 (DECHEMA's N2/H2S, p318) and its H2S cell 0.1641, which equals N2/benzene (the benzene row's N2 cell, DECHEMA p343), while its benzene cell is blank; all six DECHEMA N2/CO2 fits (pr_ip.dat rows 55 to 60) lie between -0.010 and -0.022. The reader takes the row after the diagonal one column to the right and checks every N2-column cell after the diagonal: it equals the corrected value (benzene) or copies the row's shifted cell (CO2, H2S); anything else is an error. Result: N2/CO2 -0.0193, N2/H2S 0.1652, N2/benzene 0.1641, no N2/H2O pair.
- Pairs (D3): every pair with at least one imported compound, against the imported compounds and the existing pure compounds (Water excluded: the water model). `kij_pr.dat` first (with the N2 erratum); else the `pr_ip.dat` entry whose stated temperature range is nearest 300..600 K (gap, then overlap, then file order), entries with no stated temperature only when none states one; else no pair (the method's zero).
- Owner exceptions to D3 (2026-11-04), listed with their reasons in `pair-exceptions.json` and applied before the D3 order:
  - Every Hydrogen pair is zero: no pair is written, whatever `kij_pr.dat` or DECHEMA give. The DECHEMA H2 values are narrow-range fits (H2/Toluene -0.51, H2/N-butane -0.397, H2/Propane -0.131) that would put H2 into the oil; zero is DWSIM's own default without data, and the treatment H2 gets with the crude fractions.
  - Methane/HydrogenSulfide = 0.08125, ChemSep's 2009 `pr.ipd` fit of Reamer et al. data (R. Taylor). `kij_pr.dat`'s 0.1356 equals the DECHEMA Methane/SulfurDioxide value (`pr_ip.dat` line 115) and is taken as a transcription error.
- Constant overrides: a selection entry may replace ChemSep's Tc, Pc and acentric factor (`constants`, with its source) and omit fields; every Tc-dependent value (0.95 Tc, Tr = 0.7) follows. Carbonyl sulfide takes CoolProp 8.0.0's Tc 378.77 K, Pc 6.3688 MPa, omega 0.0978 (Lemmon and Span 2006, as listed in REFINERY_COMPOUNDS_DATA.md section 2; owner decision 2026-11-04): ChemSep's record gives Tc 375.15 K while its own eq. 101 and 105 run to 378.8 K. Its triple-point pressure is omitted: ChemSep's 101.325 Pa is 1.8 times its own eq. 101 at the triple point, and no local source gives CoolProp's.
