# phase-ports-probes

Measurement drivers and gate logs of the batch `documentation/2026-09-26-phase-ports-and-compressor/`, one subfolder per work package. Nothing here is run by a Gradle task; the gates of record are the Gradle commands recorded in `PHASE_PORTS_REVIEW.md` of that batch. Written in the cloud container (OpenJDK 21.0.10, Linux); a Windows JDK 21.0.11 run differs in one ledger roundoff value (see the review, WP1 section 6).

Status: WP1-WP6 concluded 2026-09-26 (WP6); the hold work that followed (2026-09-27 to 2026-10-14, `holds*/`, `hold-fuzz/`, `hold-classes/`) concluded with the batch's close (`hold-classes/README.md`, last bullet; cleanup C2 in `documentation/2026-09-26-phase-ports-and-compressor/CLOSE_CLEANUP_REVIEW.md`, nothing left in a tracked path to detach). Every subfolder below states its purpose, the work package it served and how to run it. Code removed from a tracked path at the close is recorded in `wp6/` and `extreme/` with the removing commit, the removed source and a patch that re-attaches it. This folder is tracked on the branch (the owner's "Cloud prep" commit `ea16150` made `documentation/` and `tools/` tracked); the `logs/` subfolders are force-added because the repository's `logs/` ignore rule matches them.

Common helpers: `wp1/src/xmlsummary.py <xml dir> <junction-lines out> <test-names out>` summarises a Gradle `build/test-results/test` copy (classes, tests, failures, skipped, failing names), writes the 33 `MIXED_GAS_*`/`LIQUID_JUNCTION` lines with wall ms, bytes and allocatedMB masked, and the sorted test names; every G1 of the batch from WP1 to WP6 was summarised with it and its junction lines compared with `diff` against `d10/logs/02-junction-lines-d10.txt`. `wp1/src/cmp.py` compared the harness's test names with Gradle run 156 (the cloud harness coverage table).
