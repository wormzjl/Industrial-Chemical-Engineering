# frame-time-probe (batch 2026-10-15-custom-equipment-rendering; GPU and simulator lane for batch 2026-11-02-process-simulator)
`FrameTimeProbe.java`: the client command `/fpsprobe <warm-up s> <measurement s> <label>` and the autopilot of the FPS pairs and shader lanes (usage in `../README.md`). Measurement only. Each `FPS_PROBE` line gives the frame-interval percentiles and mean FPS, the GPU frame and screen time from a ring of 8 frames of `GL_TIMESTAMP` counters (read when available, `gpuMissed` counts the rest), and the screen's CPU time. A `FPS_LOAD` line per window gives the system CPU and the five processes that used the most cores.
Autopilot (`<game dir>/fps-autopilot/autopilot.properties`): with no `mode`, the 2026-10-15 lane (open `save`, `camera.txt`, `columns.txt`, `empty.txt`). With `mode=simulator`, it creates a fresh flat world named `save` (it refuses a save that exists), places a process simulator, measures the world with no screen, opens the block, loads the bundled crude unit, runs it to steady, then measures idle, pan, T-101's door and the Results tab, and quits. `simulator-lane/` holds that lane's `autopilot.properties` and `options.txt` (copy both to `run/mcp-client/`; `maxFps:260` is "Unlimited").
Re-attach: copy the file to `src/mcpCompat/java/com/wormzjl/icheme/mcpcompat/FrameTimeProbe.java`. It registers itself with `@EventBusSubscriber` in the `icheme_mcp_compat` mod. Then run `runMcpClient -PmcpClientWidth=1920 -PmcpClientHeight=1080` with the bridge jar in `run/mcp-client-mods/`.
