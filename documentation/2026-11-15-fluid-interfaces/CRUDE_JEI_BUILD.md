## Decisions taken in the build

1. The client re-reads each rule from the server's resolved form, not from the raw rule file the plan named. A raw file names a preset, which the client resolves only on its own bundled catalog; a server datapack with another catalog would then fail or differ. The resolved form is still read by the same `ConversionRule.parse`.
2. `ConversionLines` lives in `science/fluid/conversion/`, not `client/gui/common/` (see below).
3. The arrows are the headings' "→" and "←" (forward: "Into a liquid stream, per litre", reverse: "From a drawn phase, by mole"); JEI's API has a right arrow only.
4. Units on the JEI page are fixed °C, kPa and mol % (the page names no client unit setting).
5. The creative tab reads the bound tags when its contents are built (at login, after the tags arrive). JEI removes the placeholder at runtime start.
6. The protocol pins in `EquipmentNetworkCodecTest` and `FluidPacketCodecTest` moved from `icheme-2` to `icheme-3`: the version the brief sets. No other expected value moved.

## What the plan had wrong

- `client/gui/common/ConversionLines` cannot be named by `compat/jei`: `LayeringTest` rule `compat-free-of-client`. Moved to `science/fluid/conversion/` (it reads only `ConversionRule`). For the same reason the category names compounds itself instead of through `client/gui/common/ProcessUi`.
- "Its JSON text" alone does not let the client resolve a preset (decision 1).
