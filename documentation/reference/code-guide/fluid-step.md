## Read this when

- A step fails: `Phase/device active-set cycle`, `Device active-set limit`, `Substep refinement exhausted`, a Newton that stalls, or a `phase-hold: ...` reason.
- A flow, head or pressure in a step is wrong: a connection's row, the velocity cap, a line's static column, a pump's suction floor, a valve's mode.
- A junction or an empty vessel starts with the wrong phases, or a cold solve starts from the wrong point (the balanced start).
- A phase appears, folds or flickers between passes.
- You change what a converged step reports to the runtime (`PipeObservation`, the ledger audit).

## What it does

`PassiveStepSolver.solve` advances one island by one backward-Euler step of `dt` seconds. The unknowns are every node's state (component totals, phase splits, T, P, solid moments) and every connection's law flow, plus a device head or filter loading where present. One sparse Newton solves them all at a fixed active set: per connection a mode (`FlowControl.Mode`) and a closure, per node a phase set and a trace support. Around the Newton a pass loop changes the active set at most once per pass and solves again until the point is consistent. A solve with no carried point starts from the island's quasi-steady balance (`BalanceStart`). The step books nothing itself: `ConservativeTransport` books amounts and energy from the converged flows and `InventoryEquilibrium` closes every vessel ([fluid-interval.md](fluid-interval.md)); the solver then checks the booked point against its own equations (the equation gate) and audits the ledger (`StepObservations.checkConservation`).

The solver holds one package-private helper per stage, each built once with the solver and holding no state of its own: the balanced start, the observations, the start seeds, the movers' suction readings, the one-way closures, the device modes and the phase active set. The equations of one pass are a `StepEquations`, built per pass. The pure functions of a connection's end are `PortStreams`.

## Main flow

`PassiveStepSolver.solve(graph, dt, checkpoint, rateOnly, acceptedEndpointModes)`:

1. Start modes per connection: `DeviceModes.initialModes`. A running mover starts on its law (`MOVER_LAW`), or `CLOSED` when off, at no speed or vapour-locked (`MoverSuction.vapourLocks`). A pressure valve starts in the mode of the last accepted endpoint (`acceptedEndpointModes`, from `PassiveIntervalSolver.carriedModes`). From a carried point only a pump's suction limit or shutoff is carried (`CarriedPoint`, `carry`).
2. Closed edges, the slice's inlet refusals (`refusedInlets`), `OneWayClosures.closeDeadHeads`.
3. No carried point (`needsBalance`, `carriedPoint`): `relieveSealedPockets`, then `BalanceStart.balanceStart`; its graph, law flows, modes and closures are the solve's start (cached per input graph in `balanceFor`/`balanceCache`).
4. `OneWayClosures.closeIllegalStarts`, `relieveSealedPockets`, `reachableComponents`, `StartSeeds.initialPhaseSeeds` (last stage `arrivingPhases`).
5. Pass loop, at most `min(512, 16 + 2 nodes + 2 pipes)` passes:
   1. build a `StepEquations` (one `PhaseLayout` per node) and solve with `SparseNewton.solve`;
   2. a failed Newton reads its last iterate: `DeviceModes.cavitates`, a rigid vessel's flash, an emptying vessel (`runsDry`, laid out by `PhaseActiveSet.stockSeeds`), `DeviceModes.openStarved`, a refuted `Proposal`, `PhaseActiveSet.foldedIterate`, `drainedSeeds`; where none of these changes anything, `DeviceModes.openFailedRegulators` sets every regulating flow valve to open, once per valve per solve (`openedOnFailure`): a valve asked for more than its line passes has no root while it regulates. Then the failure is thrown;
   3. a converged pass: `reactivate`, `keptEmptying`, then at most one active-set change (device mode first, then boundary closure; a pass with a forbidden direction is phase-checked first by `phaseCorrection`), and a new pass;
   4. a pass whose flows reach a vessel it laid out dry runs `arrivingPhases` for the vessels alone (`vesselsOnly`) and solves again;
   5. a repeated `PassKey` throws `Phase/device active-set cycle`; the pass limit throws `Device active-set limit`.
6. `ConservativeTransport.reconstruct` books the converged flows; `InventoryEquilibrium.close` closes each vessel. A dry vessel the booking filled (`filled`), an appeared phase (`phaseAppeared`) or a fold (`recordFolds`) sends the loop back; `phaseCorrection` on the booked point may make a new pending `Proposal`.
7. Equation gate: the booked point's largest residual at most 1e-8 (a literal in `solve`), else `polishRefusedPoint` gets one try; then `StepObservations.checkConservation`.
8. `Result`: states, transported flows, modes, heads, inventories, boundary transfers, `PipeTransfer` samples. The interval keeps the accepted pass (`acceptedEquations`) and the bundles the next pass takes over (`preparedPass`).

The slice planners run before the step, called by `PassiveIntervalSolver`: `ports` (a running column's plans, [column-operation.md](column-operation.md)), `couple` (the coupled heat sides, once per slice) and `plan` (the local heat actuators, per step), described in [fluid-laws.md](fluid-laws.md).

## Contracts

- **The Newton only finds flows, heads and modes.** Amounts and energy come from the booking; the gate checks the booked point against the pass's own equations.
- **A pass states fixed equations.** Modes, closures, phase sets, port segments and static column ends are fixed for one Newton. Everything that decides which equations a pass states is in `PassKey`: the structure with its mode codes, closures and frozen junction donors, the phase-port segments (`StepEquations.segmentCodes`), the static column ends (`columnCodes`), the folded record, the pending proposal and the allowed-restart count. The columns are a finite record, so the sequence of passes stays finite.
- **One active-set change per pass.** A flow valve that a pass moves into `VALVE_REGULATING` restarts the pass on the balance's law flows with the node seeds kept (`PassStart.lawFlowsFromBalance`): its law flow on the old mode can stand on the saturated plateau with a slope near zero, and a junction still holding its old charge is laid out on that, not on the mixture the balance sends it. Only a converged balance (`Start.converged`) starts it; otherwise the pass starts from the converged pass's own flows, like every other change.
- **The balance is a pure function** of the step's input graph, start modes and closures; it moves no inventory.
- **Each helper reads the solver, never the reverse order.** The helpers read the solve's constants (`SolveConstants`, one per solve), the carried point and the laws through `solver`; `StepEquations` reads `rateOnly`, `constants`, `emptyings`, `suctions`, `seeding`, `sideCurve`, `lawResidual` and `moverPower`.
- **Evaluation scratch.** `StepEquations` fills pooled buffers that are written before they are read within one evaluation and never leave it (`targets`, `incoming`, `energy`, the edge pre-pass `edgeFlow`, `edgeDonor`, `edgeSuction`, a priority mixture's `donorMoles`, `suctionMoles`, `capMoles`, `carriedMoments`, `mixedMoments`, `solidMix`, `heldScratch`, and `startMoments` once per pass). The decode cache (`cachedStates`, `cachedTransport`) is not scratch: it outlives an evaluation and observers read it. A pass is evaluated by one thread at a time.
- **Observations feed nothing back.** `PipeObservation` (end pressures, elevations, section losses, flow meters, `npshRatio`, `npshRequired`, `gasRatio` (of bubbles, `SolveConstants.bubbleShares`: none in one dense fluid), `dry`, a turbine's `exhaustMoisture`, a valve's drop and `cavitation`) is read by gauges, wear, sounds and the pump page.
- **What a step reuses keeps the bits.** One edge pre-pass per evaluation (one `flow` call a connection, at most two `drawn`); pipe identities built once per graph (`identitiesOf`), a graph equal to the last keeping the last list; the four-key workspace cache keeps its eviction order (reinserting on use would change which workspace seeds the Jacobian); scheduled transfers indexed per node (`transfersAt`).
- **Determinism.** The balance's density tables (`BalanceNet.TABLE_CACHE`) and the suction floors' release and zone-edge caches (`MoverSuction`) are static synchronized `WeakHashMap`s keyed by the `State` instance; a hit returns what a recomputation would. `replayStart` drops numeric Jacobians and LU so a job does not depend on earlier jobs.

## Laws and constants

**Connection row** (`StepEquations.edgeRows`): `(P_a,end - P_b,end - rho_col g dz ± head - loss(q_law)) / pressureScale = 0`. `P_end` is the node pressure plus the port offset (`PortStreams.endPressure`); a mover's head adds, a valve's drop subtracts (`valveDrop`). `loss` is `Pipe.pressureDrop` at the law flow, in the density and viscosity of the stream drawn at the end the flow leaves ([fluid-laws.md](fluid-laws.md), `PipeResistance`). A mover's column is its suction stream's density. A passive run's column is `PortStreams.columnDensity` of the pass's column end: the line, of volume `Pipe.volume()`, filled with that port's phases in priority order by volume (`PhaseDraw.fill`); a BULK end gives the bulk. A trace at a bottom port stands as gas, not as a liquid column; gas keeps its own density in every column.

**Velocity cap** (`PassiveStepSolver.saturated`, `saturationSlope`): part of every throttling line's law, not an active set. The line carries `q = q_law (1 + (q_law/q_cap)^n)^(-1/n)`, `n` = `CAP_EXPONENT`. `q_cap` is the drawn stream's density × the line's smallest area × the velocity limit of the end the flow leaves (`massFlowLimit`; a priority mixture's pinned phases in `StepEquations.capLimit`; a filling filter's cake room in `filterCapFlow`). The saturated modes (`saturates`) are `PASSIVE`, `PUMP_SUCTION_LIMIT`, `VALVE_OPEN`, `VALVE_CONFLICT` and `MOVER_LAW`. A regulating valve states its own flow or pressure and is not saturated; one whose flow exceeds `capLimit` opens. A set-flow mover's seed flow is at most its suction end's cap. The velocity limit itself is the property model's ([fluid-thermo-port.md](fluid-thermo-port.md)).

**Junction rows** (`JunctionMixing`, `junctionInflow`, `junctionRows`). For participating stock A and incoming mass rate Q, the implicit composition balance is `(A/dt + Q) w = (A/dt) w_old + sum q w_in`. Enthalpy uses the same mass. Pressure follows the hydraulic equations. The D46 lifetime stock is fixed when the junction is minted. The active fluid and its retained reserve sum to that stock, and the reserve carries its own component amounts and enthalpy. A new moving parcel is sized using the inlet flow and `holdupTau(time)`. Lower flow can require a smaller parcel. Moving crystals retain their required carrier, and a frozen rate evaluation returns the original inventory. See [fluid-interval.md](fluid-interval.md) for the D61 melting balance.

**Suction floor** (`MoverSuction`, `ReleasePressure`). `PUMP_SUCTION_LIMIT` replaces a pump's law with `P_suction = P_floor` where it would cavitate. The floor is the greater of the clean zone's edge E and p_v plus the breakdown NPSH (`Npsh.breakdownPressure`, `Npsh.BREAKDOWN` × rho_l g NPSH3(Q, s); an in-line pump's NPSH3 from its duty, `Npsh.forDuty`): p_v is the bubble pressure of the liquid's condensable compounds drawn at its own enthalpy (one PH bisection for either liquid slot, `vapourPressure`), E the lowest pressure at which the drawn stream holds at most the clean share of vapour (`release`, `zoneEdge`, `ReleasePressure.lowest`). `release` leaves out compounds above their Tc, so a dense fluid above its Tc has no p_v (+∞): no cavitation margin, and its limit is E alone. One dense fluid has no second phase: it has no p_v in either slot (`release`), a dense trial state releases no vapour (`ReleasePressure.vapourVolumeShare` 0), and its E stands only where its isenthalp really flashes, the stream holding a vapour at the pressure found (`ReleasePressure.lowestHeld`): from the bubble side below Pc; an isenthalp on the gas side of the critical point enters the dome from the dew side and gives no edge. A dense fluid with any liquid-like weight is drawn as a liquid in either slot (`suctionFloors`, `InletPhase.Drawn.condensed`; `DenseFluidSuctionTest`). It is read where the suction walk's supplier holds gas beside the liquid and is not the pump's own first node (`suctionFloors`); the suction-limit row is `max(−flow, (P_suction − limit(Q))/scale)` (`suctionLimit`, `StepEquations`): the pump delivers the flow at which its suction stands at the limit, or nothing where its supplier cannot hold the suction there even at no flow (D17's delivery to zero, decided on the trial), with a slope in the flow on both branches. A pump whose suction head at no flow is not positive on the start states is vapour-locked for the solve and stands `CLOSED`. Once per solve `readSuctions` reads each mover's suction: a centrifugal pump's head takes `GasEntrainment.headShare` of the vapour share, a compressor's efficiency the liquid share (one dense fluid's `1 − w_pump` on a pump's own bounds 0.5 to 1.0 and `w` on the film's 0.5 to 1.5, `InletPhase.measure`; its wet gas wear reads droplets, none in one dense fluid, `Supply.dropletMassShare`); gas at a pump and liquid at a compressor refuse nothing. A mover dead-headed against a taut vessel stands on its relief line; the Newton weights a taut vessel's wall and balance rows by stiffness over `max(1e5, P)` (`StepEquations.rowWeights`).

**Device modes** (`DeviceModes.nextMode`). A mover closes on a reverse flow and reopens when its rise limit beats the demand past the band. A device closed at a discharge into a generator or a suction from a void stays closed (`forwardForbidden`). A flow valve set to no flow starts `CLOSED` unless it stands open behind a lower target (`ControlConstraints.standing`). The pressure-valve rules on the balance: a closed back-pressure valve whose balanced inlet stands above its target with a forward drive regulates, its inlet anchored at the target; a regulating valve that nothing reaches closes; one that cannot relieve its inlet at its target opens; an open valve whose inlet falls under the target regulates again. Flow valves in series carry the lower target (owner, "Lower target wins"): `ControlConstraints.standing` finds the valves that junction balances make one flow; the lowest target regulates and the others stand in `VALVE_OPEN`; the regulators go in ranked (outlet ports, inlet ports, the others, each ascending by target), and a row found dependent stands open. A pressure valve in one series with a flow regulator opens while the flow regulator regulates (`regulatesInSeries`). A flow valve that goes to `VALVE_REGULATING` at a target below the converged flow of a pump on its suction limit in its series puts that pump on its law in the same change (`lawBelowSuctionLimit`, `ControlConstraints.inSeries`): the limit does not fall as the flow falls and the suction does not either. A regulating flow valve that nothing feeds (`InletPhase.starved`) starts open, and `openStarved` re-solves a pass with it open. An open flow valve entering regulation carries the converged flows, heads and thermodynamic state when its flow remains sensitive to the pipe law. A saturated valve starts with the hydraulic balance. A failed warm transition can still retry from that balance.

**Sealed pockets** (`pockets`, `relieveSealedPockets`). A pocket is a set of junctions joined by pressure-coupling connections (`couples`) with no pressure anchor: no coupling connection to a node that is not a junction, and no regulating pressure valve drawing from it (`anchors`; a regulating flow valve prescribes a flow and anchors nothing, `flowValve`). What feeds a mover's suction must reach it and what relieves its discharge must carry flow away: a running mover with a sealed side (`sealedWithout`; a discharge that is a generator or a suction that is a void counts as one) starts `CLOSED` for the solve, the pocket held at its pressure (`StepEquations.retainedPressures`), repeated until no running mover has a sealed side. Decided at the solve's start and again when a flow valve changes mode. A mover on its law prescribes no flow, so every pocket's level keeps a row.

**Balanced start** (`BalanceStart.balanceStart`, `BalanceNet`). A point is carried (`carriedPoint`) for the same structure and the solve's own point; a rate solve carries only on value-identical states. At most `BALANCE_ROUNDS` rounds of:
1. `BalanceNet`: the junction pressures at which every junction's net inflow is zero under each open connection's own law, the loss inverted on the drive in the donor's column (`runFlow`, a search bracketed on both sides of its root), saturated at the donor's cap; nothing in a refused direction; a pump's prescribed flow or rise; a filter's cake law (`cakeResistance`). Held nodes are fixed; a regulating valve's and a suction-limited pump's junction is anchored. Unknowns are numbered breadth first for a banded Jacobian (`solveBanded`). A damped Newton (30 iterations, tolerance 1e-6 of the largest cap flow, slopes over 1e-9 of the pressure, all literals in `solveOnce`) with at most 12 Gauss-Seidel sweeps runs inside the hull of the held pressures, widened by the island's columns and pump rises. A sweep bisects each junction on the sign of its net inflow, except a sealed one (`still`: no open connection carries anything at the current pressures), which keeps its pressure; `rest` moves a junction the hull's clamp left on its bound back toward its own pressure while its connections still carry nothing. A junction that flashes reads its density and cap at its own pressure from a `TABLE`-point table in ln P (PH at its stated enthalpy; each point the fluid phases' flash `fluidPH`, a refused point the carried flash `equilibriumPH`); a junction stated as one hydrocarbon liquid reads its table only below `flashFrom` (`tabled`). Pressure-valve modes are then decided on the balanced pressures (up to 4 rounds of decisions); the balance decides no pump's mode (a pump arrives on its law, closed, or on its suction limit with its junction anchored at the floor and nothing prescribed through it), and the pass loop puts a pump on its limit. `hardClosed` holds what never reopens in the solve; `closed` also holds the device modes the balance may revise.
2. Each junction is restated as the upwind mixture the balanced flows deliver, PH at its balanced pressure (`seeded`, `mixed`; water alone by a temperature bisection). A junction that already holds that mixture is not flashed again (`holdsMixture`). A junction nothing reaches is stated as its own buffer let down at its own enthalpy (`held`; the buffers are the solve's input graph); the mint has no buffer yet and keeps the TP flash at the junction's old temperature.

A round that moves no junction pressure by more than 1e-6 of itself ends the rounds. Then each open connection gets its law flow at the balanced ends (a valve whose flow is stated gets it, `BalanceNet.flow`), and, where the balance converged, a passive connection that the balanced ends drive only the forbidden way is closed. The mint (`balanceStarts`, called by `PassiveNetwork.mintJunctions`) starts round 0 from the supplier composition (`supplierSeeds`): mover suction lines first, then the flow-weighted supplier streams flashed at the suppliers' flow-weighted end pressure, then a hop-by-hop sweep.

**Phase check and folds** (`StepPhaseRules.phaseCheck` in [fluid-solver.md](fluid-solver.md), `PhaseActiveSet.phaseCorrection`). After a converged pass each node is checked. A phase leaves only when the solve empties it: by the trace fold under `PHASE_TRACE_FRACTION`, or by vanishing (`vanishing`: below the vanishing share and shrinking by moles since the solve's start). One test states the share for `vanishing` and `nothing` (`FluidThermodynamics.belowShare`): every phase below `VANISHING_SHARE` of the node's fluid volume; water and either gas also below it by moles; the hydrocarbon liquid judged on its volume alone. A TP answer only says which phase is missing. A junction's own split is its PH answer; a vessel's is its closure from its own state at the crossing (`crossing`). A proposed phase that its own split holds below the share is refused (`nothing`). A failed iterate only folds: `collapsing` is vanishing plus any phase below `VANISHING_COLLAPSE` of its start share. A proposal that the next pass collapses is refuted and recorded. For a phase introduced by a junction starting estimate, the failed-pass check measures collapse against that estimate. Phases already present in the committed inventory retain the original comparison.

**Arriving-phase seeds** (`StartSeeds.arrivingPhases`, the last stage of `initialPhaseSeeds`). A pass is laid out for its seeds' phases, so each junction is seeded for its mixture over the step: its stock plus what its connections deliver at the pass's start flows over `dt` (its stock alone where nothing arrives), each the stream its donor end draws (`endMoles`, `endSpecificEnthalpy`), scaled to the seed's mass. The stock is what the junction's own rows mix: the buffer's amounts and its energy field (enthalpy form) less its solids' enthalpy, not the property state's specific enthalpy (the balance states a junction as what is delivered to it, which can be another mixture). It is split at the seed's pressure and the enthalpy of stock plus deliveries (`FluidThermodynamics.equilibriumPH` from the mass-weighted temperature, crystals carried; the seed keeps the junction's own solids), then folded as a junction; where the engine returns nothing the TP flash at the mass-weighted temperature stands in (`emptyBagSplit`). Where the seed is not laid out for the engine's answer (`laidOutFor`), the seed becomes the junction's own split (`StepPhaseRules.junctionSplit`) unless that split fails, empties a start phase or is the seed's layout; changed seeds go to `flashSeeds`, and a junction donor delivers its updated seed, so a phase reaches a run of junctions in one stage (at most `nodes + 1` rounds). A junction of a cold solve whose seed is the balance's restatement and which keeps at least half its stock over the step is seeded with its stock's mixture (`stocked`). Crystals never compete here. A rate-only solve does nothing here.

**Dry vessels** (`arrivingPhases`, `PortStreams.drawnStream`, `PhaseActiveSet.filled`). A vessel holding no fluid (at most `HOLDS_NOTHING` of its capacity, `holdsNoFluid`) is laid out dry until fluid reaches it, then for what arrives, PH at the enthalpy delivered. The start stage prices each delivery at the donor port's leading phase at a vanishing flow. A converged pass whose law flows reach a vessel it laid out dry (`anyDry`) runs the rule for the vessels alone (`vesselsOnly`), each connection delivering its drawn stream (`drawnStream` of `StepEquations.draws`: each drawn phase's amounts per kilogram and enthalpy, weighted by its mass flow), which is what the booking books. `filled` stays for a booking that fills a vessel past the bag's resolution though the flows delivered nothing at it.

**Flash seeds** (`StartSeeds.flashSeeds`, `settledFlash`, `restateFlashFlows`). Where a vapour appears in a junction that held none, the junction is restated where its own connections settle it: its own split marched up from the pressure the vapour appears at by `FLASH_STEP`, never past its highest neighbour, keeping the last trial whose connections still take in more than they pass. Its connections restart at their own laws at the restated ends (`PassStart.flashRestated`). A liquid condensing in a gas junction is not restated. The phase check proposes from the lowest pressure up, so a run of junctions flashes from its downstream end.

**Rigid vessel's flash** (`PhaseActiveSet.flashes`): a rigid vessel holding no gas whose draw the iterate holds below its vapour pressure is seeded at `FluidThermodynamics.equilibriumAtVolume` and the pass runs again. Before a boundary closes at a void or a generator end, the pass is solved once more with that line started the allowed way at its law flow (`allowedRestart`, once per line and solve; the count is in `PassKey`).

**Movers' booked work** (`moverPower`, the same number in the energy rows and `ConservativeTransport`): a pump's ideal work `q / rho_s × head`, all into the discharge; a compressor's polytropic work over `CentrifugalCompressor.DEFAULT_EFFICIENCY`, k from the suction (`FluidThermodynamics.heatCapacityRatio`); a plunger pump's isentropic work on the suction's exponent (`FluidThermodynamics.isentropicExponent`, through `PassiveStepSolver.suctionKappa`, the one reading the solve, a driver's charge, the view and the transport take); a centrifugal machine's over its own efficiency, cut by a wet suction (`wetShare`). The laws themselves are in [fluid-laws.md](fluid-laws.md).

**Valve regime** (`StepObservations.cavitation`, for the valve's noise): a flowing liquid valve is flashing where its outlet is below the vapour pressure, cavitating where σ = (P1 − Pv)/(P1 − P2) ≤ 1/x_Fz (x_Fz `VALVE_INCIPIENT`, IEC 60534-8-4), else plain; water by its saturation pressure, a hydrocarbon by two PH equilibria at its own enthalpy (`liquidPH`). `runtime/fluid/Noise` reads it ([effects.md](effects.md)); it feeds nothing back.

**Laws stated once here** and read elsewhere: the filter cake law `cakeResistance` (the balance's slope, the edge row's loss, `NetworkReduction.resolutionFlow`), the mixing-enthalpy bisection `BalanceStart.mixingBracket`, the incidence table `incidence`.

## Traps

- **`PassiveNetwork` is not passive**, and **`Reservoir` means any node**; see [fluid-interval.md](fluid-interval.md).
- **A carried start needs the same lines.** `replayStart` keeps the committed interval only where `sameLines` holds; a change it does not excuse (anything but a flow valve's set point, a column's boundary plan and a shaft train's plan, `PassiveNetwork.Pipe.Identity.sameLine`) starts the job from the balance, which on a large island costs hundreds of times more and can pass the wall budget.
- **The edge unknown is the law flow, not the flow carried.** A line deep in saturation has `q_law` far above `q`. `replayStart` loads the transported flows as both the carried point's `flows` and its `lawFlows`, so a saturated line restarts at `q_law = q`, about 8 % under its carried flow; the Newton reaches the same root.
- **A rate solve (`solveRate`, dt = 1) is not a step.** It holds junction compositions at their buffers and books their accumulation as `HeldJunctions`; phase-port capacities are infinite. A cold structure's first step starts from a rate solve's point (`coldRateSeed`), and a rate solve without a carried point is itself balance-started (`needsBalance` does not test `rateOnly`).
- **Two passes with the same modes are not the same pass.** A pass states its static columns from its own seed (`StepEquations.columnEnds`); a new per-pass choice that changes a row's value without a structural entry belongs in `PassKey` too.
- **A junction's arriving-phase seed is a PH split, not a TP flash**, and the engine's answer is only the start of the junction's own split (`junctionSplit`).
- **`balanceStart` has two overloads.** The five-argument one passes the solve's input graph as the junctions' buffers; the mint calls the six-argument one with `buffers` null.
- **A balance table is not always a table.** `TABLE_CACHE` also keeps an entry with no table for a liquid junction that does not flash inside the hull; test `tabled`, not `tableP[j] != null`.
- **The step's caches are keyed by `State` alone.** `State` is a record over `double[]` fields with no `equals` override, so a hit needs the same state instance; the caches are shared by every solver of the process.
- **A melting junction's `possible` components.** Where any junction melts a crystal, each node holding a crystal admits that crystal's component among the components it can bring, so a melting junction's rows have the component's unknown.
- **`targetVolumeFlow` is not the setting.** A mover stores `requestedVolumeFlow` and `enabled`; `targetVolumeFlow()` is 0 while it is off.
- **`columnDensity` and "static column"** mean the fluid standing in a line or port, not the distillation column.
- **Find the parts of `PassiveStepSolver` by name**, in file order: the private `solve` (a failed solve leaves `carry` as it found it, so a retry at a shorter interval starts from the point the failed attempt started from) and `solvePasses` (the pass loop, ending at the `Device active-set limit` throw), the slice planners `plan`, `couple` and `ports`, and the mint's `balanceStarts`. All row assembly is `StepEquations` (layout, draws, rows and block Jacobian in one class: its constructor sets the fields all three read). Most constants carry their measurement history in Javadoc: read it before changing one.
