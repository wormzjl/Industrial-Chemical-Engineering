## Read this when

- You are about to change code and need to know which Gradle task, test class or fixture proves the change.
- A report or review says "gates", "lane" or "final lane", "javac lane", "quick check" or "quick lane", "campaign", "cold random", "class C/F hold", "phase hold", "junction lines", "MIXED_GAS_COST" or "chain-100" and you need to know what is meant.
- A test class is named `G3F1`..`G3F10`, `G4F1`, `G4F2` or `G5F1`..`G5F6` (the thermo qualification families, not the gates).
- You prepare a merge to `main` (CHANGELOG, `mod_version`, tooling cleanup, log check, code guide).
- A test fails only on another JDK, or a solver regression reference must be re-recorded.
- You change a fluid facts schema, an equipment shape field or a layout, and must add a corpus image or update the layout table under `src/test/resources/compat/` (AGENTS.md, "Saves and data formats").

## In one paragraph

The mod builds with ModDevGradle (`net.neoforged.moddev` 2.0.143) on a Java 21 toolchain, for Minecraft 1.21.1 / NeoForge 21.1.219, with `mod_version` in [gradle.properties](../../../gradle.properties) as the only version number. There are four source sets: `main`, `test` (JUnit 5, 346 tracked Java files including helpers, which also sees the Minecraft classpath so wire and NBT codecs are tested for real), `fluidGameTest` (21 Java files: server GameTests, their helpers, the review world and the paced benchmark, loaded only by their own run configurations) and `mcpCompat` (a small mixin mod for the MCP test client). The plain `test` task runs everything except `fluid/benchmark/**`; dedicated tasks run the fluid science and runtime packages, the exact solver regression (`chain-100`) and the Holland column benchmark. The equilibrium engine's tests (`science/thermo/**`), the material catalogue's (`science/material/**`) and the column's (`science/column/**`) have no dedicated task: only the full `test` runs them. The owner's "gates" are not a Gradle task: the final lane is a shell script in the git-ignored `tools/` folder (`lane.sh`) that runs, in sequence, the full `test` (it serves as G1 and G3; its 33 junction lines, `MIXED_GAS_COST` and other printed lines are compared with the previous lane's), the exact regression (G2), the fluid GameTests (26 at 71ad53ef; 34 in the source at this snapshot) on a fresh run id (G5) and a 1000-seed campaign. Save compatibility is held by gates inside `test` that read the checked-in corpus under `src/test/resources/compat/` (old saves as images, never player worlds). Solver changes are judged by that placement-sequence fuzz ("hold fuzz", also in `tools/`), run as a 200-seed quick check or a 1000-seed campaign in three report sets (cold random on the pilot cryogenic package, bundled random, bundled defaults) and classified into hold classes. AGENTS.md limits how these are run: at most two Gradle invocations at once, timing runs alone, and the lean measurement rule.

## Native-default integration qualification

When CMake is found, `processResources` obtains the platform library through `nativeConfigure`, `nativeBuild` and `nativeResources`; the jar carries it under `natives/<os>-<arch>/`. `NativeColumnSolverTest` is in the quick suite and checks packaged default/fallback loading, agreement with the Java PR kernel and product agreement with either outer pass. `nativeSmoke` remains the explicit JNI smoke task. The default inside-out PR outer pass can be disabled with `-PnativeThermoBatch=false`; `-PnativeLibraryPath` sets the library path for Gradle test JVMs. No library means the Java fallback. See [the native-default review](../../2026-10-28-native-column-default/NATIVE_DEFAULT_REVIEW.md) for the original qualification and [the integration review](../../2026-10-28-vacuum-column/INTEGRATION_REVIEW.md) for combined quick/slow results with the vacuum fix. This feature-branch integration adds no test task or gate classes.

`V3VacuumStartupTest` adds seven ordinary gate tests: the captured false-phase startup and bad handoff, dry-prefix ledger structure, zero-reflux steam column, dry gas pressure drop, full side-cut/pumparound dry-top column, and continuation through the 900 K caloric edge. Accepted dry gas is independently TP-flashed at the model's steam-adjusted hydrocarbon pressure. The unchanged `test` task runs them; no new Gradle task or product probe was added.

`src/test/resources/column/vacuum-startup.json` preserves the original CDU-bottoms feed and observed false startup/handoff states. `invalid-binary-roots.json` contains actual numerical roots and final-step certificates captured at `494d3e45`; fresh solver/audit/hot-start checks retain their negative phase coverage without requiring today's cold trajectory to find them. Positive hot-start, command and learned-recovery fixtures use independently accepted live-boilup states. The old 551 K binary becomes an explicit phase-audit rejection test. Conservation and acceptance tolerances are retained.

The offline export/trace/fixture tools live in `tools/vacuum-column-test/`, with all run outputs under registered worktree `tmp/`. <details><summary>Regression fixtures and how they are re-recorded</summary>

- `chain-100` is a synthetic 100-reservoir cosine-pressure chain built in code (`SolverRegressionHarness.cosineChain`), replayed for one 5 s interval and compared with [chain-100.json](../../../src/test/resources/fluid/regression/chain-100.json). It is the only fixture. It was last re-captured on 2026-10-28 (4521b65c): the second-virial steam moved each unit's 0.2 mol of water past the 1e-6 gate (moles 2.7e-6 relative, temperature 5.7e-5 K); the replay is exact against the new capture. The three island fixtures that needed a stress-world snapshot (`quiet-11312`, `quiet-11324`, `cold-11312`), the `-PfluidRegressionSnapshot` switch and the `FLUID_REGRESSION_SNAPSHOT` alias were removed on 2026-10-15; nothing wrote that snapshot any more.
- Gates: `declared` (default) is 1e-6 relative on pressure, mass, volume and totals, 1e-4 K, 1e-6 on phase fractions, 1e-3 on average flows; `exact` requires bitwise equality (G2 prints `max deviation 0.000e+00`).
- Re-record: `gradlew fluidSolverRegression -PfluidRegressionCapture=true` writes the references in place. To prove a change is bitwise neutral against the previous commit without touching the committed file, capture into a scratch directory with `-PfluidRegressionReferences=<dir>` on the old commit, then run `exact` against it on the new one.
- A re-record is a reviewed event, named in the CHANGELOG. `git log -- src/test/resources/fluid/regression/chain-100.json` lists them; the last ones: `a0f20364` (2026-10-16: water at 997.05 kg/m3, a full tank delivers its own expansion), the 0.7.0 squash `1dba69b3` (the JDK-determinism re-baseline), `c7a7dc26`, `3c840367`. A capture that reproduces the reference bit for bit leaves the file unchanged in git.
- The report goes to `build/reports/fluid/solver-optimization.json` (`SolverRegressionHarness.REPORT`) with wall ms, allocation and solver counters per interval. The counters are read generically through `SolverDiagnostics.names()`, so the printed table and the report list every counter the product carries; tolerances and the single fixture do not depend on them.

## Which check decides what

Follows the lean measurement rule in AGENTS.md (forms on the quick check, one campaign for the chosen form, one final lane, which is the rule's single gates run).

| Kind of change | Minimum checks |
|---|---|
| Fluid solver or network physics, comparing up to three forms | `quick-lane.sh` (Gradle-free) or `lane.sh <sha> quick` per form: 200 seeds, cold random, bundled random and defaults; choose one |
| The chosen solver form | `lane.sh <sha>` once (full test, G2, GameTests on a fresh run id, the 1000-seed campaign on 8 workers); replay alone only new C/F holds, batched; trace at most the two smallest new worse worlds |
| A refactor meant to be trajectory-identical | G2 `exact` (chain-100), the full test's junction lines, `MIXED_GAS_COST` and printed lines unchanged; between commits `lane-check.sh` (every printed line bitwise on the javac lane; the column tests only in Gradle) |
| A new gate test | That test with the rule disabled (fails), then with it (passes); not the whole suite |
| Fluid runtime, scheduler, checkpoint or presentation | `fluidRuntimeTest`; `runFluidGameTestServer` (fresh run id) when blocks, menus or saves are involved |
| Elementary math or thermo kernels | `fluidScienceTest` (incl. `DeterministicMathSourceTest`), `test --tests 'com.wormzjl.icheme.science.thermo.*'` and `'com.wormzjl.icheme.science.material.*'` (the engine, the G3-G5 families, the Helmholtz oracle, which `fluidScienceTest` does not reach), G2 exact; the JDK sweep only if determinism is in question |
| V3 column | `test --tests 'com.wormzjl.icheme.science.column.v3.*'`; `v3HollandBenchmark` for accuracy claims; `runColumnGameTestServer` for the admission path |
| Materials data | `verifyMaterialIndex` (via `processResources`), `science.material.*` tests |

## Terms

- **Gates (G1/G2/G3/G5)**: the fluid suites with junction lines, exact chain-100 regression, the 7-class adjacent selection, the fluid GameTests (26 at 71ad53ef, 36 in the source at this snapshot); run by `lane.sh`, whose full `test slowGates` serves as G1 and G3 (earlier batches: `gates.sh`).
- **Junction lines**: the 33 `LIQUID_JUNCTION`/`MIXED_GAS_*` lines printed by the two junction transient tests, compared textually with `ms=` masked.
- **MIXED_GAS_COST**: one printed line of `MixedGasJunctionTransientTest` (12 cases, `newtonSolves`, ms, MB); the Newton solve count is the cost counter (299 at this snapshot).
- **chain-100**: the 100-reservoir cosine-pressure regression fixture and its committed reference state.
- **Hold**: an island that publishes a HELD status instead of advancing; classified by `classify.sh` into classes A, B, C (typed phase hold), D, E1-E10, F (wall deadline), G, X.
- **Phase hold**: the typed capability hold, status prefix `HELD (phases): `, class C.
- **Quick check**: 200 fuzz seeds in the three report sets, `lane.sh <sha> quick` or the Gradle-free `quick-lane.sh` ("quick lane"); the older `quick.sh` compared them with a full campaign's same seeds.
- **Campaign**: `lane.sh <sha> campaign`, 1000 fuzz seeds in the three report sets on 8 workers.
- **Distribution**: `random` (random block specs) or `defaults` (world-default specs) of the hold fuzz; the three report sets are cold random (the pilot package), bundled random and bundled defaults.
- **Pilot package**: `icheme:pilot_cryogenic`, the test datapack's network package (`PilotCryogenicTestCatalog`), also the cold fuzz's package.
- **Qualification families**: the thermo test classes `G3F*`, `G4F*`, `G5F*` in `science/thermo/qualification/`.
- **Fresh world**: a new run directory; no test runs against a player world (AGENTS.md).
- **Corpus image**: a checked-in old save under `src/test/resources/compat/` (a fluid checkpoint per facts schema, saved shell tags per shape-field revision) that the compatibility gates read at every run.
- **Layout table**: `compat/layouts/layouts.txt`, what 81 reference shapes place; `EquipmentLayoutGoldenTest` fails on any change until it is updated.
- **Lane**: one Gradle invocation in AGENTS.md (at most two non-timing lanes at once, timing runs alone); the final lane, one `lane.sh` run (logs `mNN`); the javac lane, the Gradle-free compile-and-run of a `git archive` export.
