- You are about to change code and need to know which Gradle task, test class or fixture proves the change.
- A report or review says "gates", "lane" or "final lane", "javac lane", "quick check" or "quick lane", "campaign", "cold random", "class C/F hold", "phase hold", "junction lines", "MIXED_GAS_COST" or "chain-100" and you need to know what is meant.
- A test class is named `G3F1`..`G3F10`, `G4F1`, `G4F2` or `G5F1`..`G5F6` (the thermo qualification families, not the gates).
- You prepare a merge to `main` (CHANGELOG, `mod_version`, tooling cleanup, log check, code guide).
- A test fails only on another JDK, or a solver regression reference must be re-recorded.
- You change a fluid facts schema, an equipment shape field or a layout, and must add a corpus image or update the layout table under `src/test/resources/compat/` (AGENTS.md, "Saves and data formats").

## In one paragraph

The mod builds with ModDevGradle (`net.neoforged.moddev` 2.0.143) on a Java 21 toolchain, for Minecraft 1.21.1 / NeoForge 21.1.219, with `mod_version` in [gradle.properties](../../../gradle.properties) as the only version number. Create (with Ponder, Flywheel and Registrate) and KubeJS are optional mods since batch 2026-11-03-rotating-machinery W6a (`neoforge.mods.toml` `optional`): `compileOnly`, and loaded in the dev runs, tests and GameTests through the `optionalModRuntime` configuration; `-PwithoutCreate` drops all five from those runtimes for the check without Create. Only `compat/create/**` names a Create type ([rotating-machinery.md](rotating-machinery.md)). There are four source sets: `main`, `test` (JUnit 5, 467 Java files including helpers, which also sees the Minecraft classpath so wire and NBT codecs are tested for real), `fluidGameTest` (29 Java files: server GameTests, their helpers, the review worlds and the paced benchmark, loaded only by their own run configurations) and `mcpCompat` (a small mixin mod for the MCP test client). The plain `test` task runs everything except `fluid/benchmark/**`; dedicated tasks run the fluid science and runtime packages, the exact solver regression (`chain-100`) and the Holland column benchmark. The equilibrium engine's tests (`science/thermo/**`), the material catalogue's (`science/material/**`) and the column's (`science/column/**`) have no dedicated task: only the full `test` runs them. The owner's "gates" are not a Gradle task: the final lane is a shell script in the git-ignored `tools/` folder (`lane.sh`) that runs, in sequence, the full `test` (it serves as G1 and G3; its 33 junction lines, `MIXED_GAS_COST` and other printed lines are compared with the previous lane's), the exact regression (G2), the fluid GameTests (26 at 71ad53ef; 37 in the source at this snapshot) on a fresh run id (G5) and a 1000-seed campaign. Save compatibility is held by gates inside `test` that read the checked-in corpus under `src/test/resources/compat/` (old saves as images, never player worlds). Solver changes are judged by that placement-sequence fuzz ("hold fuzz", also in `tools/`), run as a 200-seed quick check or a 1000-seed campaign in three report sets (cold random on the pilot cryogenic package, bundled random, bundled defaults) and classified into hold classes. AGENTS.md limits how these are run: at most two Gradle invocations at once, timing runs alone, and the lean measurement rule.

To prove a change is bitwise neutral against the previous commit without touching the committed file, capture into a scratch directory with `-PfluidRegressionReferences=<dir>` on the old commit, then run `exact` against it on the new one.

A capture that reproduces the reference bit for bit leaves the file unchanged in git.
- The report goes to `build/reports/fluid/solver-optimization.json` (`SolverRegressionHarness.REPORT`) with wall ms, allocation and solver counters per interval. ## Terms

- **Gates (G1/G2/G3/G5)**: the fluid suites with junction lines, exact chain-100 regression, the 7-class adjacent selection, the fluid GameTests (26 at 71ad53ef); run by `lane.sh`, whose full `test slowGates` serves as G1 and G3 (earlier batches: `gates.sh`).
- **Junction lines**: the 33 `LIQUID_JUNCTION`/`MIXED_GAS_*` lines printed by the two junction transient tests, compared textually with `ms=` masked.
- **MIXED_GAS_COST**: one printed line of `MixedGasJunctionTransientTest` (12 cases, `newtonSolves`, ms, MB); the Newton solve count is the cost counter (299 at this snapshot).
- **chain-100**: the 100-reservoir cosine-pressure regression fixture and its committed reference state.
- **Hold**: an island that publishes a HELD status instead of advancing; classified by `classify.sh` into classes A, B, C (typed phase hold), D, E1-E10, F (wall deadline), G, X.
- **Phase hold**: the typed capability hold, status prefix `HELD (phases): `, class C.
- **Quick check**: 200 fuzz seeds in the three report sets, `lane.sh <sha> quick` or the Gradle-free `quick-lane.sh` ("quick lane"); the older `quick.sh` compared them with a full campaign's same seeds.
- **Campaign**: `lane.sh <sha> campaign`, 1000 fuzz seeds in the three report sets on 8 workers.
- **Distribution**: `random` (random block specs) or `defaults` (world-default specs) of the hold fuzz; the three report sets are cold random (the pilot package), bundled random and bundled defaults.
- **Pilot package**: `icheme:pilot_cryogenic`, the test overlay's network package (`PilotCryogenicTestCatalog`; not bundled), also the cold fuzz's package.
- **Tia Juana overlay**: the Tia Juana Light assays, presets and the `tjl19_dwsim` package as test data only (`TiaJuanaTestCatalog`, `TiaJuanaExtension`); the game ships the four generated grades.
- **Qualification families**: the thermo test classes `G3F*`, `G4F*`, `G5F*` in `science/thermo/qualification/`.
- **Fresh world**: a new run directory; no test runs against a player world (AGENTS.md).
- **Corpus image**: a checked-in old save under `src/test/resources/compat/` (a fluid checkpoint per facts schema, saved shell tags per shape-field revision) that the compatibility gates read at every run.
- **Layout table**: `compat/layouts/layouts.txt`, what 81 reference shapes place; `EquipmentLayoutGoldenTest` fails on any change until it is updated.
- **Lane**: one Gradle invocation in AGENTS.md (at most two non-timing lanes at once, timing runs alone); the final lane, one `lane.sh` run (logs `mNN`); the javac lane, the Gradle-free compile-and-run of a `git archive` export.
