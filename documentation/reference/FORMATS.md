# Saved and wire formats

Every saved and wire format of the mod, with its current value and the constant that declares it. Read from the code at `259d22a2c`, 2026-11-13. Paths are under `src/main/java/com/wormzjl/icheme/` unless they start with `src/test`. Kinds: **facts** (what the player built and put in; never discarded), **state** (the engine computes it again; a mismatch drops it), **wire** (client and server packets; no compatibility, AGENTS.md "Saves and data formats").

A batch that changes a format changes its row here in the same commit. Where to take the next number: [COLLABORATION.md](COLLABORATION.md), "Numbers". `FormatsTableTest` checks each row: every `Class#FIELD` against the row's value, every inline string and digest tag against the file named.

## Wire protocols

Every payload registrar of the mod carries one version, [`network/NetworkProtocol.java`](../../src/main/java/com/wormzjl/icheme/network/NetworkProtocol.java), `NetworkProtocol.VERSION` (codebase review P3-22). NeoForge negotiates each payload channel (its type id) at login, with the version of the registrar it was registered on: a client and a server whose versions differ on any channel, or where one lacks a channel the other requires, are refused with the channels and the reasons (`NetworkComponentNegotiator`). None is optional. So client and server must be the same version of the mod. Bump the version at any change of a payload's bytes, type ids or registration. `icheme-2` (batch 2026-11-15-equipment-visual-design): a steam turbine's inlet class gained LP, declared first, so the design point's steam ordinal (`EquipmentNetwork.writeDuty`, 0 for none, else the ordinal plus one) moved for every class. `icheme-3` (batch 2026-11-15-fluid-interfaces): the conversion rules sync, `FluidNetwork.ConversionRulesSync` (S→C, each loaded rule's id and its file with names resolved, at login and after each reload, on `OnDatapackSyncEvent`); and the alarm beacon's edit (`alarm_edit`) and view (`alarm_view`) payloads (W9); the controllers' `control_browse` also pages a beacon's input choices. `icheme-5` (batch 2026-11-16-fouling-corrosion, WP3; `icheme-4` was reserved by `2026-11-15-supercritical-fluids` and not used): the constructor's design (`EquipmentNetwork.ConstructorPayload`) carries the structure's material of construction by name after the still's options; a name the server does not have reads carbon steel. WP4 adds, under the same version: the constructor's `EquipmentNetwork.Repair` (C→S: constructor, structure origin, its stamp, request) and `RepairAnswer` (S→C, sent from the queued repair's reply), `StructureState` (C→S, with the screen's placement line, bounded by the server) and `StructureStateAnswer` (S→C: worst used wall allowance, −1 for no wall, and the state words, at most 64 characters); a device view (`FluidView`, JSON in the fluid menu payloads) carries `integrity` (used share, rate mm/y, mechanism and material by name, life in play seconds) and `trim` (health, life in play seconds), each null when absent; a shell cell's update tag carries `Weeping` (presentation only, never saved). WP5 adds, under the same version: the heat page's Clean (`FluidNetwork.CleanPayload`, C→S, `fluid_clean`: menu id, position, identity; the answer is a chat line from the queued repair's reply); a device view's `heat` carries `fouling` (m²K/W), and the unit's `ua` and `uaClean` (W/K, D16), each null when absent. WP8 adds, under the same version: the column's operation view (`AssemblyNetwork.writeOperation`) carries, after the trays, its unit's wear where it has a unit (tray fouling, wall left as a share of the allowance, wall rate mm/y, material as an enum ordinal); the conditions gain `TRAYS_FOULED`, `THIN_WALL`, `WEEPING` and `LEAKING`, appended; the Operation tab's `AssemblyNetwork.Action` gains `CLEAN`, appended, answered by a chat line from the queued clean's reply.
