## W7 findings

- Stop's reach. `CancellationException` is an `IllegalStateException`, and the neural correction's catch eats it (`V3ColumnCalculator` line 290, again 1206, and the `advisory` at 514 publishes on the authored drop). The flag stays set, so the next checkpoint throws; a second checkpoint after each law closes the case of the last calculation. "Native" is no gap: the game's path calls C++ only for `pengRobinsonBatchTemperatureDerivatives`; `NativeColumnSolver.solve` has no caller, and Newton runs in Java between checkpoints.
- Stop's speed. Cold column on the sample, normal priority: 878 521 checkpoints, gap median 0.7 us, 99.9 % 3.7 ms, longest 38.9 ms, in `verifyFinalNewtonCorrection`. So Stop lands within 39 ms of the thread being scheduled. On a machine saturated by other Java runs a low-priority thread waited up to 2.7 s, and the same run took 100 s against 11 s; on the machine free, 9 s. That is the scheduler, not the code.
- Shared with a world: nothing it can disturb. A run builds its own `FluidThermodynamics` and `FlowThermo`; `MaterialRuntime.with` confines the catalog; nothing in `science/` fans out to threads; the neural model is immutable and its inference holds only locals; the C++ library has no static state. Mutable statics on the path: `MaterialRuntime.active` (read once at a run's start), and `SolverDiagnostics.ENABLED`, off unless someone switches its opt-in instrumentation on, when a run's flashes would join its static list.
- One thing a clock can move. `V3ColumnCalculator` gives the learned start 2 s and the hydraulic correction 10 s of wall clock. Spent differently, a solve takes another path and ends in different last digits. It did not happen in the gates, but a low-priority run on a saturated machine is where it would, and `SimulatorRunTest`'s digit gate is the one that would show it.
- The catalog. `MaterialRuntime.publish` is called only by the server's reload listener, and `IChemE` resets it when a server stops, so `active()` is the server's in single player, the bundled one on a dedicated server's client, and the bundled one again after a world is left. A run takes it once, on the caller. Read from the code; no client ran.
- The render thread. The screen built a `SheetState`, with its signature strings, on every frame and key: it now keeps one per sheet and run by identity, and only the run's clock is new each time. `StreamProps` reads viscosity correlations, no flash, and is kept on that state. The stream templates' `FluidPresetCatalog.resolve` ran each frame a dialog stood open: once on opening now. Folders are read away from the frame.
- 3 passes against 2. The sheets' H-101 has `limit` 90 MW and the W3 gate's has none. Pass 1 has no hot residue in E-101, so the furnace needs 103.63 MW. Capped at 90, the column gets a colder feed and its bottoms come out at 277.5 °C, not 300.2 °C. S-9 then moves 5.5 % in pass 2, and pass 3 closes. Uncapped, pass 1 is right the first time and pass 2 closes.
- P-102, for the owner. Expected: a draw leaves its tray at the bubble point of that tray, but a steam-stripped tray's total pressure is not the oil's: the vapour is 23.9 % steam, so the oil's partial pressure is 196.4 kPa of the 258.2 kPa. S-8 holds no water, so on its own it needs its pressure to fall to about that before it boils. What the code did: `FlowThermo.bubblePressure` gives 191.5 kPa at S-8's 486.44 K, 74.2 % of the stream's pressure, within 2.5 % of the partial pressure, and `MoverUnit` asks at 99.9 %, so it stays silent. That is right: the pump has about 67 kPa in hand. Proposal: leave the law, and read the warning on the design sheet, which was written by hand, as a mistake of that sheet. Nothing changed.

## W7 decisions

Taken alone, each reversible:

- Solve alone's stream is the line's last solved state, greyed or not: in a loop, the column's own edit greys its feed, which is exactly when a player wants it. A line that feeds the unit from the sheet needs no run. Off, with a hover, only where a run never left one.

The sheet's status, loops and gaps are a run's to say, so they stand, Sizing stays off, and the status line says what happened. A failed or stopped solve changes nothing and says why. Only the last one counts: a second greys the first. Each starts cold.

- `attempt` runs a second checkpoint after each law, so `FlowsheetSolverTest`'s stop count went from 3 to 5.
- A token is `fluidRevision`, not `Basis.revision`: a package's own revision does not move when a record it names does, so it would keep results a data edit has outdated. `RevisionNotice.tokens(sheet, catalog)` also takes each column door's package.
- A notice takes the short form of the status before it, because the line does not wrap; a narrow window drops the package's name.
- The column's Templates dialog has Cancel and Load: Delete and Save current wait for W8's Save as template. Rows take the old rows' ids in order, so a stream stays on its port, and a cooler's drop or a pump stands. With no feed a template applies as written.

- Log: the order lists parts as `T-101/pa 1`, and the sheet's grouped wording is left out. A pass's first line gives the tear's outlet temperature, its next how far it moved. The hot sides are a `margin` reading of the column's checks, in K. Sheets 22 and 23 are new numbers.
